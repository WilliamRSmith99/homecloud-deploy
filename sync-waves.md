# Sync waves

Argo CD syncs the child Applications generated by the root app in ascending
`argocd.argoproj.io/sync-wave` order. Lower (more negative) goes first; Argo
waits for every resource in a wave to be Healthy before starting the next.

Without waves the first sync fails on missing CRDs, then succeeds on retry. It
works, but every rebuild looks broken. The waves below make the ordering
explicit.

| Wave | Contents | Why |
|-----:|----------|-----|
| `-3` | argocd (self-managed) | Argo reconciles its own chart before it manages anything else |
| `-2` | sealed-secrets, cert-manager, cnpg-operator | CRDs must exist before anything references them |
| `-1` | traefik, tailscale-operator, cloudflared | Networking before workloads |
| `0`  | monitoring (kube-prometheus-stack, Loki, Grafana), argo-workflows, argo-events, actions-runner-controller | Platform services |
| `1`  | postgres-cluster | Needs the CNPG operator from wave -2 |
| `2`  | apps (overlap-bot, llm-router, embedding-service, power-controller, pr-review-bot) | Need Postgres and networking |

## How a wave is set

The annotation goes on the child `Application` manifest in
`bootstrap/applications/`, not on the component's own manifests:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: sealed-secrets
  namespace: argocd
  annotations:
    argocd.argoproj.io/sync-wave: "-2"
```

Resources with no annotation are wave `0`. Keep app-of-apps waves spaced by
whole numbers so a component can be inserted later without renumbering.
